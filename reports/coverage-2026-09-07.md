## 6. Tests à écrire — Liste priorisée

### Lot 1 🔴 — Flux critiques sans aucune couverture

#### TEST-01 : `/api/groups/[id]/tournaments/[tid]/magic-link` (GET/POST/DELETE)

Cas à couvrir :
- [ ] POST sans auth → 401
- [ ] POST par non-admin → 403
- [ ] POST par admin → retourne `{ token: string }` (UUID)
- [ ] POST une 2e fois → désactive le premier lien (vérifier `isActive: false` en DB)
- [ ] GET par admin → retourne le lien actif
- [ ] DELETE par admin → désactive le lien actif ; GET retourne null
- [ ] Accès invité avec token révoqué → 401 (via `/api/guest/validate`)

#### TEST-02 : `/api/groups/[id]/guests/[accessId]` (PATCH)

Cas à couvrir :
- [ ] PATCH sans auth → 401
- [ ] PATCH par non-admin → 403
- [ ] PATCH par admin sur accès PENDING → status devient ACCEPTED
- [ ] PATCH sur accès REVOKED → comportement défensif (400 ou no-op)
- [ ] Email `sendGuestApprovedEmail` est appelé sur succès (mock)
- [ ] `findAcceptedForUser` retourne l'accès après PATCH

### Lot 2 🟠 — Routes importantes sans couverture

#### TEST-03 : `/api/users/search` (GET)

Cas à couvrir :
- [ ] Sans auth → 401
- [ ] `q` < 3 caractères → 400
- [ ] `q` ≥ 3 caractères → retourne liste (sans passwordHash)
- [ ] Résultats limités à 10

#### TEST-04 : `/api/guest/my-tournaments` (GET)

Cas à couvrir :
- [ ] Sans auth → 401
- [ ] Utilisateur non-invité → 403 (ou liste vide selon l'implémentation)
- [ ] Invité avec accès ACCEPTED → retourne les tournois accessibles
- [ ] Invité avec accès REVOKED → tournoi absent de la liste

#### TEST-05 : `/api/admin/users/[id]/groups` (POST)

Cas à couvrir :
- [ ] Sans auth → 401
- [ ] Non-admin → 403
- [ ] Admin, `groupIds` valides → user ajouté à chaque groupe
- [ ] Admin, `groupIds` invalides → 400
- [ ] User déjà membre → no-op (pas de doublon)
