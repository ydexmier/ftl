## Priorités

### 🔴 Lot 1 — Tests critiques

**`magic-link` + `guests`** — Feature invité, logique de mutation d'état.

- `GET /api/groups/[id]/tournaments/[tid]/magic-link` → 401, 403, 200 (null si aucun lien)
- `POST /api/groups/[id]/tournaments/[tid]/magic-link` → 401, 403, 404 (tournoi non attaché), 201, unicité (2ème POST désactive le 1er)
- `GET /api/groups/[id]/tournaments/[tid]/guests` → 401, 403, 200 vide, 200 avec accès PENDING

### 🟠 Lot 2 — Tests utiles

**`admin/users/[id]/groups`** — Route admin add user to group.
- POST → 401, 403, 400 (groupId absent), 404 (groupe inconnu), 201

**`users/search`** — Recherche utilisateurs.
- GET → 401, 400 (q < 3 chars), 200 (résultats max 10)

**`admin/groups/[id]/invitations/[invId]`** — Annulation invitation.
- DELETE → 401, 403, 404 (invitation inconnue ou groupe mismatch), 400 (non-PENDING), 200

**`RegistrationService.fetchAndSave` multi-pages** — Le cas `total > PAGE_SIZE` déclenche des fetches parallèles non testés.

### 🟡 Lot 3 — Tests complémentaires

**`GroupMagicLinkRepository.upsert`** — Vérifier que l'ancien lien est bien désactivé (isActive=false) avant la création.

**`TournamentExternalAccessRepository.findPendingByGroupAndTournament`** — Vérifier que seuls les accès PENDING sont retournés, pas les ACCEPTED ou REVOKED.

**`mergeDeep`** — Couvrir les cas de fusion imbriqués et les tableaux.
