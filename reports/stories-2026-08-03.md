## ARCH-01 — Supprimer `connectToMongoDB()` redondant dans `api-tokens/[tokenId]/route.ts`

**Contexte :** `app/api/groups/[id]/tournaments/[tid]/api-tokens/[tokenId]/route.ts` (ligne 18) appelle directement `connectToMongoDB()` avant d'invoquer `ApiTokenRepository.revoke()`. Ce repository gère lui-même la connexion. La même violation a été corrigée sur les fichiers voisins le 2026-06-09 mais ce fichier enfant a été oublié. Le pattern `connectToMongoDB()` dans les routes API est une violation de l'architecture : la connexion appartient au repository, pas à la route.

**Critères d'acceptation :**
- [ ] `import connectToMongoDB from '@/src/lib/db'` supprimé du fichier
- [ ] `await connectToMongoDB()` (ligne 18) supprimé
- [ ] Les tests existants dans `api-tokens.test.ts` passent toujours (la suppression n'affecte pas le comportement)
- [ ] `grep -r "connectToMongoDB" app/api/` ne retourne plus que les routes `test/seed`

**Effort :** XS  
**Dépendances :** Aucune  
**Source :** Rapport

## SEC-01 — Vérifier la route `/api/auth/logout` sans rate limiting

**Contexte :** `app/api/auth/logout/route.ts` est une route POST publique sans `checkRateLimit`. Le risque est faible (invalide une session DB, pas de création de ressource), mais un flood permettrait de saturer les requêtes DB de révocation de session. Toutes les autres routes POST publiques mutables ont un rate limiting. La cohérence de défense en profondeur suggère d'aligner.

**Critères d'acceptation :**
- [ ] `checkRateLimit('logout:${getIp(request)}')` ajouté avec une limite haute (ex. 30 req/15min par IP)
- [ ] `getIp` importé depuis `@/src/lib/auth/getIp`
- [ ] Un test vérifie que 31 requêtes rapides retournent 429

**Effort :** XS  
**Dépendances :** Aucune  
**Source :** Rapport

## TEST-01 — Tests pour `PUT /api/groups/[id]/guests/[accessId]` (approve/reject/revoke)

**Contexte :** Cette route gère le cycle de vie des accès invités (approve → email envoyé, reject, revoke). Elle contient des validations de statut, des vérifications de propriété cross-group, et un effet de bord email (`sendGuestApprovedEmail`). Aucun test d'intégration n'existe pour cette route critique du flux invité.

**Critères d'acceptation :**
- [ ] `approve` sur un accès PENDING → status ACCEPTED, retourne 200
- [ ] `reject` sur un accès PENDING → status REJECTED, retourne 200
- [ ] `revoke` sur un accès ACCEPTED → status REVOKED, retourne 200
- [ ] `approve` sur un accès non-PENDING → 400
- [ ] Non-admin du groupe → 403
- [ ] `accessId` appartenant à un autre groupe → 403
- [ ] Email mocké : `sendGuestApprovedEmail` appelé une fois lors d'un approve
- [ ] Tests dans `guest-access.test.ts` ou un nouveau `guest-approval.test.ts`

**Effort :** M  
**Dépendances :** Aucune  
**Source :** Rapport

## TEST-02 — Tests pour les nouvelles routes de gestion des invités

**Contexte :** Trois routes liées au flux invité n'ont aucun test d'intégration :
- `GET /api/groups/[id]/tournaments/[tid]/guests` — liste les invités PENDING
- `GET /api/tournaments/[id]/member-groups` — retourne les groupes dont l'utilisateur est membre pour un tournoi
- `DELETE /api/groups/[id]/invitations/[invId]` — annule une invitation de groupe PENDING

**Critères d'acceptation :**

_`GET /api/groups/[id]/tournaments/[tid]/guests` :_
- [ ] Retourne les accès PENDING avec les données utilisateur associées
- [ ] Non-admin du groupe → 403
- [ ] Aucun invité → retourne une liste vide

_`GET /api/tournaments/[id]/member-groups` :_
- [ ] Utilisateur membre d'1 groupe sur 3 → retourne uniquement ce groupe
- [ ] Utilisateur non membre → retourne `{ groups: [] }`
- [ ] Non authentifié → 401

_`DELETE /api/groups/[id]/invitations/[invId]` :_
- [ ] Admin annule une invitation PENDING → 200
- [ ] Non-admin → 403
- [ ] Invitation ACCEPTED → 400 "ne peut plus être annulée"
- [ ] `invId` appartenant à un autre groupe → 404

**Effort :** S  
**Dépendances :** Aucune  
**Source :** Rapport

_`GET /api/admin/users/[id]/reports` :_

_`POST /api/admin/users/[id]/groups` :_

- [ ] `groupId` manquant → 400
- [ ] Groupe inexistant → géré proprement (not 500)

_`DELETE /api/admin/groups/[id]/invitations/[invId]` :_
- [ ] Admin annule une invitation → 200
- [ ] Non-admin → 401
