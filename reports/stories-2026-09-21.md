## SEC-01 — Ajouter rate limiting sur `/api/external/tournaments/[id]/players`

**Contexte :** La route publique d'API externe n'a pas de rate limiting par IP, contrairement à toutes les autres routes publiques mutables ou sensibles du projet. Un acteur malveillant peut faire des milliers de requêtes avec des tokens invalides, forçant à chaque fois un hachage SHA-256 et une requête MongoDB.

**Critères d'acceptation :**
- [ ] `checkRateLimit(`external-api:${getIp(request)}`)` appelé en début de handler `GET`
- [ ] Clé `external-api:*` documentée dans le fichier `rateLimit.ts` (commentaire ou constante nommée)
- [ ] Réponse 429 retournée si dépassement
- [ ] Test d'intégration : après 5 requêtes rapides depuis la même IP, la 6e retourne 429

**Effort :** XS  
**Dépendances :** aucune  
**Source :** Rapport

## REFACTO-01 — Clarifier useFetch vs fetch direct dans `ApiTokensTab.tsx`

**Contexte :** `ApiTokensTab.tsx` réimplémente manuellement le pattern loading/error/data pour le GET initial (lignes 42-53) alors que `useFetch<T>` fait exactement cela. Le hook `useFetch` ne supporte pas le rechargement impératif (`refresh()`) après mutation, ce qui oblige à rester sur fetch direct pour la cohérence. Cette story consiste d'abord à décider d'une convention.

**Critères d'acceptation :**
- [ ] Option A : étendre `useFetch` avec un `refresh()` callback → `ApiTokensTab` utilise le hook
- [ ] Option B : documenter dans CLAUDE.md la convention "fetch direct acceptable pour les composants mutants qui gèrent leur propre state"
- [ ] Le composant résultant ne duplique pas le pattern loading/error si `useFetch` peut être utilisé

**Effort :** S  
**Dépendances :** aucune  
**Source :** Rapport

## TS-01 — Typer les pipelines MongoDB avec `PipelineStage[]`

**Contexte :** 5 variables de pipeline MongoDB sont typées `any[]` dans `RoundRepository.ts` et `TournamentPlayersDeckRepository.ts`. Depuis Mongoose v7, le type `PipelineStage` (importable depuis `mongoose`) couvre exactement ces cas et activerait la vérification TypeScript sur les étapes du pipeline.

**Critères d'acceptation :**
- [ ] `import type { PipelineStage } from 'mongoose'` ajouté dans les 2 fichiers
- [ ] `const pipeline: PipelineStage[]` remplace `const pipeline: any[]` dans les 5 occurrences
- [ ] `as any` ligne 142 de `TournamentPlayersDeckRepository.ts` typé de façon plus précise ou commenté
- [ ] `npm test` passe à 100%
- [ ] `tsc --noEmit` passe sans erreur

**Effort :** S  
**Dépendances :** aucune  
**Source :** Rapport
